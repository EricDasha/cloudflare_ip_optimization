## 一、这是什么项目

`G:\EricDasha.github.io\cloudflare` —— 昵称 **cloudflare-tools**，代号「皇位厅 / 三层漏斗」。

一个 Go 写的 Cloudflare 优选代理池管理器。目标：从多个供给源拉取 CF 优选 IP/优选域名，
经过三层漏斗（初筛 → WS 101 握手 → VLESS 终审）筛出可用目标，交由 `cfnat` 做本地 TCP 转发，
客户端连 `192.168.1.50:1234` 即可出网。部署在 NAS（fnOS）上跑 Docker。

四个运行面（`DESIGN.md:5-10`）：

| 组件 | 职责 |
|---|---|
| `cloudflare-web` | HTTP API + 静态 GUI + 进程生命周期 + 候选缓存/生效池落盘 |
| `cfnat` | 纯 TCP 转发，一个客户端连接绑一个上游 IP，拨号失败才顺序回退 |
| `cfdata` | IP 发现扫描器。**代码实况：有 6 小时后台自扫**（`web/main.go:140,218-209`，`CFDATA_AUTO_SCAN` 默认 true），读 `result.csv` 供候选汇合（`web/cfdata_supply.go:96`）。但 DESIGN.md:144-161 与 README.md:104,238 均称「彻底手动化」—— **文档与代码矛盾，见缺口 2** |
| `sing-box` | 短命 VLESS 数据面探针，非常驻代理 |

## 六、硬核实操教训（值得保留）

1. **压缩不能救超限 session**：压缩本身要发请求，上下文涨到发不出去时压缩请求也发不出去 → 永远 running。必须在超限前触发。
2. **TCP 通 ≠ 服务可用**：`openssl s_client` 测 `127.0.0.1:1234` 只验证本地段；被阻断的是 cfnat → CF:443 那一段，只有完整 VLESS 链路能验证。
3. **SNI 阻断**：同 IP 不同 SNI 结果不同。`curl https://IP/`（SNI=IP）通，VLESS 连同 IP 带域名 SNI 超时。
4. **「保留旧池」不等于「旧池活着」**：这是 2026-10-22 事故真正根因 —— 系统对外显示 healthy，实际池已全死。已由 `aad595d` 修。
5. **退避不能退化成永久拉黑**：若全部源都在退避期，放弃退避全量重试（`web/candidates.go`）。
6. **段配额必须轮转，不能贪心**：贪心时排在前面的段吃满名额，后面的段永远进不来，等于没有多样性。
7. **兜底放行的触发条件是 `len==0` 不是「不足下限」**：不足就补会把 dead/unstable 拉进来凑数，破坏既有测试。
8. **30s 总超时会误杀并发源**：不是源挂了，是总预算把整批并发请求一起判死 → 放宽到 90s。
9. **假优选识别**：CF 段命中率 0% 的源（lzj/luoli/xinyitang3/kristi/yutian）是第三方 VPS 冒充优选，不得加入。
